PanSSR: End-to-End SSR Discovery, Marker Development, and Genotyping

This page is designed for GitHub Pages hosting and aims to be a full, transparent technical guide. It explains what PanSSR does, why each step exists, and how to run it at small and large scale (including HPC). No major stage is treated as a “black box.”

What PanSSR solves

PanSSR automates SSR marker workflows over many genomes: discovery of tandem repeats, functional annotation, primer design, in-silico validation, cross-genome polymorphism ranking, and optional population genotyping from BAM files. It supports both command-line execution and a Streamlit GUI.

1) Core concepts and background theory

1.1 What is an SSR?

An SSR (Simple Sequence Repeat, microsatellite) is a short motif (1–6 bp in this tool) repeated in tandem (e.g., ATATATAT). SSR length variation across genomes or individuals creates useful molecular markers for genotyping and breeding.

1.2 Why pangenome SSR marker design is hard

  • Many loci appear in one genome but not others.
  • Primer sites can be non-specific or absent in some genomes.
  • Some loci are monomorphic (not useful as markers).
  • Overlapping annotations create ambiguity in biological interpretation.

1.3 Theory behind each major stage

SSR detection

Pattern scanning with repeat thresholds by motif length detects perfect tandem repeats. This is computationally efficient and deterministic.

Feature annotation

Interval overlap maps markers to genes/exons/introns/UTRs using interval indexing for fast queries.

Primer design + ePCR

Primers are designed on flanking sequence, then checked in silico for amplicon behavior to screen unreliable loci early.

Polymorphism filtering

A marker is retained when observed amplicon/repeat differences are biologically consistent and useful for discrimination.

2) Pipeline architecture

Input genomes + annotations
   ├─ SSR discovery
   ├─ Annotation overlap
   ├─ Primer design
   ├─ ePCR simulation
   └─ Marker filtering
        ├─ markers.tsv (main)
        ├─ markers.tsv.matrix.tsv (cross-genome matrix)
        └─ markers.tsv.common_poly.tsv (support-threshold set)

Optional genotype mode:
   markers.tsv + BAMs + reference -> genotypes.csv

4) Quick start commands

Genome mode

python main.py --mode genome \
  --genome_dir ./genomes \
  --annot_dir ./annotations \
  --output markers.tsv \
  --min_genome_support 80

Genotype mode (parallel)

python main.py --mode genotype \
  --reference ref.fasta \
  --markers markers.tsv \
  --bam_dir ./bams \
  --output genotypes.csv \
  --workers 16

5) Genome mode in detail

  1. Load genome/annotation file pairs.
  2. Discover SSR loci per sequence.
  3. Annotate with genomic features.
  4. Design primers on flanks and run ePCR checks.
  5. Classify marker type (SSR/VNTR) and tag is_cSSR, is_iSSR.
  6. Filter to quality marker candidates.
  7. Write marker table and cross-genome summaries.

6) Cross-genome matrix and common polymorphic set

The matrix output consolidates markers by locus key and records per-genome repeat values. The common polymorphic set filters loci where:

  • polymorphism is observed (≥2 repeat states), and
  • support is at least --min_genome_support genomes.

For 100 genomes, set:

  • --min_genome_support 100 for “present in all genomes”, or
  • --min_genome_support 80 (or similar) for “present in most genomes”.

7) Genotype mode in detail

Reads overlapping each marker are parsed with CIGAR-aware logic to recover repeat-support evidence robustly. BAM files can be processed in parallel via --workers.

9) Performance, memory, and HPC execution

  • Low-memory flow: genome-mode writes filtered results progressively.
  • Parallel genotyping: set --workers to your node core count.
  • Deterministic I/O: sorted file discovery and stable output order improve reproducibility.
# Example SLURM-style command
python main.py --mode genotype --reference ref.fa --markers markers.tsv \
  --bam_dir /scratch/bams --output genotypes.csv --workers ${SLURM_CPUS_PER_TASK}

11) Output schema reference

markers.tsv

genome_id, chrom, start, end, motif, repeat_count, annotation, primers, amplicon_sizes, marker_type, is_cSSR, is_iSSR

markers.tsv.matrix.tsv

Per-locus support matrix with polymorphism and per-genome values.

markers.tsv.common_poly.tsv

Support-threshold polymorphic subset for marker panel construction.

genotypes.csv

Per-sample per-marker genotype calls and allele-support counts.

12) Troubleshooting and validation

  • If no markers survive filtering, verify annotation pairing and primer/ePCR constraints.
  • If call rate is low, inspect mapping quality/read support thresholds.
  • Use tests for sanity checks:
pytest -q

For scientific reporting, keep software version, CLI command, and parameter values with each run.
